On-ramp · TRY → USDC

TRYbank transfer→ TRY balance→ USD/TRYquote→ USDCto wallet
  1. The user logs in with their Stellar key (SEP-10) and starts a deposit
  2. The anchor returns bank details: an IBAN and a reference to write in the transfer description (açıklama)
  3. You play the bank in this sandbox: the TRY "arrives" and is credited
  4. The rate is locked at USD/TRY (Reflector oracle + spread) via a SEP-38 quote
  5. Real testnet USDC is paid to the user's wallet (or held until a trustline exists)

Off-ramp · USDC → TRY

USDC+ memo→ USDC received→ USD/TRYlocked→ TRYto IBAN
  1. The user starts a withdrawal and gets the treasury address + a memo id
  2. The wallet sends USDC on Stellar testnet with that memo
  3. The anchor detects the payment and sells at the locked rate
  4. TRY is paid to the user's IBAN (simulated FAST)
  5. Both sides track status through SEP-6 /transaction

Two paths, one ledger

SEP path · standard, portable (start here)

stellar.toml discovery (SEP-1), /auth (SEP-10), /sep6 deposit & withdraw, /sep12 simulated KYC (no personal data), /sep38 quotes. Non-custodial: the user's key is the identity. Integrate once, ship to any real SEP anchor by changing the home domain. The SEP path →

API path · optional business layer (not portable)

A custom /v1 REST API with an API key, for a business backend that orchestrates many users server-side (webhooks, event feed, back-office). Its endpoints are specific to this mock and do not exist on a real anchor. API demo + reference →

export KEY=trma_test_…
