A Turkish TRY ⇄ USDC on/off-ramp you can build against today.

API-key based, modelled on how Turkish exchanges actually ramp: bank transfer with a reference code → TRY balance → USDC on Stellar. The bank is simulated; the Stellar leg is real testnet USDC. Sign up with your email and get one API key — or watch the whole round trip run live first.

One account per email, one API key per account. You can rotate it any time from the dashboard.

On-ramp · TRY → USDC

  1. POST /v1/customers → customer with a deposit reference
  2. GET /v1/customers/{id}/deposit-instructions → our IBAN + the reference the user writes in the transfer description (açıklama)
  3. POST /v1/sandbox/bank-transfers → you play the bank: the TRY arrives, the balance is credited
  4. POST /v1/quotes → USDC/TRY rate locked 120 s (Reflector USD/TRY oracle + spread)
  5. POST /v1/onramps → TRY debited, real testnet USDC paid to the wallet (payment or claimable balance)

Off-ramp · USDC → TRY

  1. POST /v1/offramps → treasury address + memo id
  2. Wallet sends USDC on Stellar testnet with that memo
  3. We detect the payment, sell at the locked rate, credit TRY
  4. auto_payout → TRY “sent” to the customer's IBAN (simulated FAST)
  5. Track with GET /v1/offramps/{id}, webhooks, or GET /v1/events

Two doors, one ledger

Partner API · X-API-Key

How Turkish exchanges expose ramps to integrators: your backend holds a key, you own the UI, you drive customers, quotes, on-ramps and off-ramps through /v1. Sign up above.

⚠ Production Turkish ramps differ in predictable ways — OAuth2 + scopes + IP allowlist instead of a key, swap-based conversion, real compliance fields. What will change on mainnet.

SEP-6 door · wallets

Standards-compliant: stellar.toml discovery (SEP-1), /auth (SEP-10), /sep6 deposit & withdraw, /sep12 simulated KYC (no personal data), /sep38 quotes. Try it in the Stellar demo wallet: add asset USDC with home domain tr-mock-anchor.fly.dev. Verified with SDF's anchor-tests. Details.

Quickstart

curl -X POST $BASE/v1/partners -H 'content-type: application/json' \
  -d '{"email":"you@example.com","password":"correct-horse-battery","name":"My app"}'
# → { "api_key": "trma_test_…" }

export KEY=trma_test_…
curl -X POST $BASE/v1/customers -H "X-API-Key: $KEY" -H 'content-type: application/json' \
  -d '{"first_name":"Ayşe","last_name":"Yılmaz","iban":"TR330006100519786457841326"}'
# → { "id": "cus_…", "deposit_reference": "TRMA-XXXX-XXXX", ... }

curl -X POST $BASE/v1/sandbox/bank-transfers -H "X-API-Key: $KEY" -H 'content-type: application/json' \
  -d '{"reference":"TRMA-XXXX-XXXX","amount_try":"1000.00"}'

curl -X POST $BASE/v1/onramps -H "X-API-Key: $KEY" -H 'content-type: application/json' \
  -d '{"customer_id":"cus_…","amount_try":"1000.00","destination_address":"G…"}'
# poll GET $BASE/v1/onramps/{id} until status = completed → stellar_tx_hash
