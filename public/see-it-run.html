This is the SEP-6 door. Here it is, running.

A throwaway wallet did a complete TRY → USDC → TRY round trip through this anchor's SEP-6 interface — the standardized, wallet-interoperable door. No API key. No password. No sign-up form. Every number and hash below is from that real run against tr-mock-anchor.fly.dev; the on-chain legs are real Stellar testnet transactions anyone can inspect.

This page shows the SEP-6 door. The same anchor also has an API-key door (the partner REST API) — watch that one in the interactive demo. Same anchor, same treasury, same ledger: two doors.

What makes this door different

  • No API key, no password. Auth is SEP-10: the anchor sends a challenge, the wallet signs it with its own Stellar key. The key is the identity.
  • KYC is simulated and silent. SEP-12 is advertised, but this sandbox asks for no personal data.
  • The bank leg is simulated; the chain leg is real. The two stellar.expert transaction links below prove real testnet USDC moved.
  • Zero bespoke integration. Any wallet that speaks SEP-6 can use this anchor today — that is the point of the standard.

The eleven steps, exactly as they happened

1

SEP-1: the wallet discovers the anchor

Everything starts with one unauthenticated GET. The stellar.toml tells any wallet where every door is.

curl https://tr-mock-anchor.fly.dev/.well-known/stellar.toml

WEB_AUTH_ENDPOINT="https://tr-mock-anchor.fly.dev/auth"      # SEP-10 auth
TRANSFER_SERVER="https://tr-mock-anchor.fly.dev/sep6"        # SEP-6 deposits/withdrawals
KYC_SERVER="https://tr-mock-anchor.fly.dev/sep12"            # SEP-12 KYC (simulated)
ANCHOR_QUOTE_SERVER="https://tr-mock-anchor.fly.dev/sep38"   # SEP-38 quotes
SIGNING_KEY="GDXYO6FJCNXZEWGXD54GT76FGFYLOLSOGSOJLNQ6WGHCGEQPO7NTE73M"
2

Wallet setup: keypair, Friendbot, trustline

A fresh keypair is generated locally, funded with test XLM by Friendbot, and given a trustline to the anchor's USDC. This is the entire "account creation" — no registration with the anchor.

Keypair.random()                                  # generated locally; the secret never leaves the wallet
GET https://friendbot.stellar.org?addr=GDDO4EEK…  # fund with test XLM
changeTrust(USDC:GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4NAT4AQH3ZLLFLA5)
3

SEP-10: log in by signing, not by password

The wallet asks for a challenge transaction, signs it with its own key, and posts it back for a JWT session token. No email. No password. The key is the identity.

# 1. Ask for a challenge — the only "credential" is the public key
curl "https://tr-mock-anchor.fly.dev/auth?account=GDDO4EEKWQNZ3KDXITG6DJUBRZVHAX45IUVSMGPT4J4OZOMPUGZMBHHV"

{ "transaction": "<challenge XDR>", "network_passphrase": "Test SDF Network ; September 2015" }

# 2. Sign the challenge with the wallet's key, post it back
curl -X POST https://tr-mock-anchor.fly.dev/auth \
  -H "content-type: application/json" \
  -d '{"transaction":"<signed challenge XDR>"}'

{ "token": "<JWT>" }   # the session — send as Authorization: Bearer on every SEP-6 call
4

SEP-6 /info: what the anchor offers

The anchor reports deposit and withdraw for USDC: fee 0.5%, minimum 0.5, maximum 25000.

curl https://tr-mock-anchor.fly.dev/sep6/info

{
  "deposit":  { "USDC": { "enabled": true, "min_amount": 0.5, "max_amount": 25000, "fee_percent": 0.5, … } },
  "withdraw": { "USDC": { "enabled": true, "min_amount": 0.5, "max_amount": 25000, "fee_percent": 0.5, … } },
  …
}
5

Deposit: ask for TRY-in instructions

One authenticated GET starts the deposit. The anchor returns an order id and Turkish bank instructions: send TRY to the anchor's IBAN with a reference code in the transfer description (açıklama). In SEP-6 that reference field is organization.external_transfer_memo.

curl -H "Authorization: Bearer <JWT>" \
  "https://tr-mock-anchor.fly.dev/sep6/deposit?asset_code=USDC&account=GDDO4EEKWQNZ3KDXITG6DJUBRZVHAX45IUVSMGPT4J4OZOMPUGZMBHHV&amount=1000"

{
  "id": "<order id>",
  "how": "Bank transfer (FAST/EFT) to TR050009900000000000000001",
  "instructions": {
    "organization.bank_account_number":   { "value": "TR050009900000000000000001", "description": "IBAN (TR Mock Bank A.S.)" },
    "organization.external_transfer_memo": { "value": "TRMA-MX42-FL9U", "description": "Write this reference in the transfer description" }
  }, …
}
6

Status: waiting for your transfer

The wallet polls the standard transaction endpoint. pending_user_transfer_start means "we gave you bank details; we're waiting for the money" — this is what a wallet renders as "waiting for your transfer".

curl -H "Authorization: Bearer <JWT>" \
  "https://tr-mock-anchor.fly.dev/sep6/transaction?id=<order id>"

{ "transaction": { "kind": "deposit", "status": "pending_user_transfer_start", … } }
7

Play the bank (sandbox only)

In production the customer really sends TRY and the bank notifies the anchor. Here the incoming transfer is simulated — the only step of the eleven that isn't exactly what production looks like. Everything else on this page is the standard flow.

The simulated bank leg is the sandbox's one cheat. The chain leg that follows is not simulated.
8

Settle: the anchor pays real USDC on chain

The status walks pending_anchor → completed, and the anchor's treasury sends a real Stellar testnet payment to the wallet.

{ "transaction": {
    "status": "completed",
    "amount_in":  "1000.00",       # TRY received by bank transfer
    "amount_out": "20.5404656",    # USDC paid on-chain
    "amount_fee": "4.98",          # TRY (the 0.5% spread)
    "stellar_transaction_id": "b5d901f52e16700acefeeff273c3e743214819accb1156b65d0e7cb3341a215e" } }
⛓ Proof: the USDC payment on stellar.expert
9

Balance check: the wallet really holds the USDC

Horizon confirms the wallet's balance: 20.5404656 USDC. Not a number in the anchor's database — a balance on the public ledger, visible on the wallet's account page.

10

Withdraw: ask for the reverse route

The mirror image of step 5. The anchor answers with its treasury account and a memo (type id) that routes the incoming payment to this order.

curl -H "Authorization: Bearer <JWT>" \
  "https://tr-mock-anchor.fly.dev/sep6/withdraw?asset_code=USDC&type=bank_account&amount=20.54"

{
  "id": "<order id>",
  "account_id": "GCLCZEQZ2THTEDAOFI66LACNPLY4OBKN7VKLEZFMBIHYKYQOW2W7T3Z6",   # the anchor's treasury
  "memo_type": "id",
  "memo": "691439819827"
}
11

Send the USDC back; get TRY out

The wallet pays the treasury on chain with the memo. The anchor's watcher detects the payment on Horizon and pays out TRY (simulated FAST): 20.54 USDC in → 990.02 TRY out.

payment(destination = GCLCZEQZ2THTEDAOFI66LACNPLY4OBKN7VKLEZFMBIHYKYQOW2W7T3Z6,
        asset = USDC, amount = 20.54)  + memo(id) 691439819827

# then the same GET /sep6/transaction?id=… ends at:
{ "transaction": { "status": "completed", "amount_in": "20.54", "amount_out": "990.02" } }
⛓ Proof: the incoming USDC payment on stellar.expert

Try it yourself — five minutes, no account

  1. Open demo-wallet.stellar.org and generate + fund a testnet account.
  2. Add an asset with home domain tr-mock-anchor.fly.dev and add the USDC trustline.
  3. Start a SEP-6 deposit (not SEP-24 — this anchor's door is SEP-6). The wallet will do SEP-1, SEP-10 and SEP-6 for you, exactly as above.
  4. When the deposit shows "waiting for your transfer", open the transaction's more-info link to simulate the bank leg, then watch real USDC arrive.
